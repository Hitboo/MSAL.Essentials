# Commit-messages

Please read this article - so you know how to properly write commit messages:  
[How to Write a Git Commit Message](https://cbea.ms/git-commit/)

## Rules for commit messages

1. Separate subject from body with a blank line
2. Limit the subject line to 50 characters
3. Capitalize the subject line
4. Do not end the subject line with a period
5. Use the imperative mood in the subject line
6. Wrap the body at 72 characters
7. Use the body to explain what and why vs. how

## Verbs used for commit messages

Here's a list of commonly used verbs for git-commit-messages with their explanations and an examples illustrating their appropriate usage:

| Verb      | Explanation (used when)                                  | Example                                               |
|-----------| ---------------------------------------------------------|-------------------------------------------------------|
| Add       | adding new files, features, or functionalities.          | "Add user registration functionality"                 |
| Document  | adding or updating documentation.                        | "Document API endpoints in the README file"           |
| Implement | adding new features or functionalities.                  | "Implement search functionality in the sidebar"       |
| Update    | modifying or updating existing code, files, or data.     | "Update README.md with installation instructions"     |
| Fix       | fixing bugs, errors, or issues.                          | "Fix null pointer exception in the login module"      |
| Merge     | merging branches or integrating changes.                 | "Merge feature branch into development"               |
| Beautify  | improving the appearance or aesthetics of code or UI.    | "Beautify the side-navigation with better colors"     |
| Chore     | doing miscellaneous tasks or maintenance activities.     | "Chore: Format code according to style guide"         |
| Refactor  | restructure code without changing its external behavior  | "Refactor code to improve readability"                |
| Reformat  | reformatting/restructuring code for better readability.  | "Reformat code to follow consistent indentation"      |
| Relocate  | move files without changing their names                  | "Relocate docs for project-labels to conventions"     |
| Remove    | deleting or removing code, files, or features.           | "Remove obsolete function from the API"               |
| Rename    | changing the name of files, variables, or functions.     | "Rename main.js to app.js for better clarity"         |
| Optimize  | improving performance or efficiency of code.             | "Optimize database query for faster response times"   |
| Test      | adding or modifying tests for code.                      | "Test edge cases in the validation module"            |
| Bump      | incrementing version numbers or dependencies.            | "Bump version to 1.2.0"                               |
| Revert    | reverting changes to a previous state.                   | "Revert commit xyz to fix unintended side effects"    |
